## このプロジェクトの目的

Neuromedia LDPlayer Software Rendering は、適切な GPU がない Windows マシン、または RDP 経由で利用するサーバー上で、LDPlayer 14 をソフトウェアレンダリングで起動するための準備を支援します。このような環境では Android エミュレーターが利用可能な OpenGL コンテキストを取得できず、起動中の停止、黒い画面、予期しない終了が起こることがあります。本プロジェクトは Windows 全体のグラフィックスタックを書き換えるのではなく、利用者が確認した Mesa/llvmpipe のファイルを **LDPlayer のフォルダー内** に配置する方式です。

これはエミュレーター本体でも、LDPlayer の改造版・再配布版でもありません。CMD/PowerShell スクリプトと手順書により、必要な DLL の存在、x86/x64 の一致、所定のコピー先、`GALLIUM_DRIVER=llvmpipe` の設定を確認しやすくします。llvmpipe は主に CPU で描画します。そのため GPU が利用できない状況で起動できる可能性はありますが、性能、消費 CPU、同時実行数、アプリ互換性を保証するものではありません。

## インストーラーの動作

`1_INSTALL.cmd` は管理者権限で `install.ps1` を起動します。現在のスクリプトは、期待される LDPlayer ディレクトリと `mesa/x86`・`mesa/x64` のソースファイルを検査し、該当パスの LDPlayer プロセスを停止します。続いて Mesa と識別された DLL またはシンボリックリンクだけを削除し、各アーキテクチャ向けに `opengl32.dll`、`libgallium_wgl.dll`、`libglapi.dll` をコピーします。最後にマシン環境変数 `GALLIUM_DRIVER` を `llvmpipe` に設定し、ファイル、PE アーキテクチャ、環境変数の診断を表示します。実行記録はリポジトリ直下の `install.log` に出力されます。

`2_CHECK.cmd` は変更を加えない確認専用モードです。DLL の存在、検出されたアーキテクチャ、システム変数を表示します。LDPlayer の更新や再インストールは DLL を削除・置換することがあるため、その前後に必ず確認してください。「OK」はスクリプトの期待条件を満たしたことを示すだけで、任意のゲーム、Android イメージ、業務アプリがサポートされることを意味しません。

## 前提条件と事前準備

`install.ps1` に記載された既定の対象パスは次のとおりです。

```text
D:\LDPlayer\LDPlayer14\              # dnplayer.exe: x86 Mesa DLL
C:\Program Files\ldplayer9box\       # Ld9BoxHeadless.exe: x64 Mesa DLL
```

実際のインストール先が異なる場合は、実行前に `install.ps1` の `$ld` と `$box` を編集してください。名前だけで判断せず、それぞれの実行ファイルが本当にあることを確認します。x86 プロセスに x64 DLL を、あるいはその逆を渡してはいけません。アーキテクチャ不一致は DLL ロード失敗や起動失敗の直接の原因になります。

作業前に全 LDPlayer インスタンスと関連ツールを終了し、メンテナンス時間を確保してください。対象ディレクトリのバックアップと、現状ファイル一覧の記録を推奨します。組織管理下やクラウド環境では、RDP、ソフトウェア導入、ライセンス、変更管理、セキュリティに関する規則への適合も先に確認します。マシン環境変数を変更した後は、RDP からサインアウトして再ログインするか、再起動してから新しいプロセスを開始してください。既に動いているプロセスに値は自動で反映されません。

## Mesa DLL の入手、ライセンス、検証

この公開リポジトリは Mesa バイナリーを意図的に同梱していません。以前の非公開キットにあった DLL には、完全なライセンス文書、公式配布 URL、検証可能な来歴が添付されていなかったため、公開再配布には適しません。利用者は、Windows と対象アーキテクチャに対応し、使用条件と出所が明確なビルドを自ら合法的に入手する必要があります。

配布条件が明確な提供元から Windows 用 Mesa ビルドを取得し、ライセンス、notice、URL、バージョン、ハッシュを保管してください。[THIRD_PARTY_BINARIES.md](../THIRD_PARTY_BINARIES.md) の構成に従い、`mesa/x86/` と `mesa/x64/` の両方に三つの DLL を配置します。配布元の SHA-256 などで検証し、`assets/mesa-binaries.example.sha256` が単なる書式例であることにも注意してください。Mesa のライセンス情報は <https://docs.mesa3d.org/license.html> にありますが、ネット上の任意の DLL アーカイブを無条件に再配布できるという意味ではありません。

## 推奨する導入手順

1. 本書、`THIRD_PARTY_BINARIES.md`、`SECURITY.md` を読み、LDPlayer の版と実パスを記録します。
2. 対象ディレクトリをバックアップし、正当に入手した DLL、ライセンス、ハッシュを用意してアーキテクチャを確認します。
3. メンテナンス時間内に LDPlayer を終了し、`2_CHECK.cmd` を実行して導入前の結果を保存します。
4. 信頼できる管理者アカウントで `1_INSTALL.cmd` を実行し、UAC を承認します。表示内容と `install.log` を確認します。
5. サインアウト/サインインまたは再起動後、再度 `2_CHECK.cmd` を実行します。両方のフォルダーに正しい x86/x64 DLL があり、マシン変数が `llvmpipe` であることを確認します。
6. 重要ではない単一インスタンスで起動、ログ、アプリ動作を試験してから範囲を広げます。CPU、メモリー、RDP 応答性を監視してください。

実行中のインスタンス上で DLL を上書きしないでください。また、出所不明のバッチで Windows のシステムグラフィック部品を置換したり、ライセンス、アクセス制御、アンチチート、組織規則、サービス提供者の制限を回避する用途に使ったりしてはいけません。

## ロールバックと問題の切り分け

戻す場合は、まず LDPlayer を完全に停止します。この手順で導入した三つの DLL だけを二つの対象ディレクトリから削除し、マシンの `GALLIUM_DRIVER` を削除して、バックアップを復元します。ある DLL が Mesa のものか不明なら、推測で削除しないでください。先にコピーを保全し、プロパティと来歴を調べます。`install.ps1` のコメントには識別・削除範囲の説明もあります。

よくある原因は、対象パスが実際のインストール先と異なる、ソース DLL が不足している、x86/x64 を取り違えた、再ログイン前で変数が見えない、更新でファイルが上書きされた、といったものです。エラー時は `install.log`、LDPlayer バージョン、匿名化したパス、ハッシュ情報を保存してください。RDP パスワード、私設 IP、顧客データ、未検証の実行ファイルを公開チャンネルに送らないでください。
